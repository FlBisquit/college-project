## Соглашение о коммитах

#### Префиксы

| Префикс | Когда использовать |
| :--- | :--- |
| `feat:` | Новая функциональность |
| `fix:` | Исправление бага |
| `refactor:` | Рефакторинг (процесс изменения внутренней структуры) без изменения поведения |
| `wip:` | Незавершённая работа (как срочный коммит) |
| `docs:` | Изменения только в документации |
| `style:` | Форматирование, пробелы — без изменения логики |
| `test:` | Добавление или исправление тестов |
| `perf:` | Улучшение производительности |
| `chore:` | Зависимости, конфиги, инструменты |
| `build:` | Сборочная система, скрипты |
| `revert:` | Откат предыдущего коммита |

### Примеры

```
feat(auth): добавил авторизацию через JWT
fix(api): исправил падение при пустом токене
refactor: вынес логику валидации в отдельный модуль
docs: обновил README, добавил примеры запросов
test: добавил unit-тесты для authService
revert: feat: добавил авторизацию через JWT
```

## Запуск проекта

**Backend**
```bash
cd backend
python manage.py runserver
```

**Frontend**
```bash
cd frontend
npm install
npm run dev
```

**Redis**
```bash
redis-server
```

**Celery**
```bash
celery -A config worker --loglevel=info --pool=solo
```

**Tests**
```bash
cd "название приложения"
pytest tests.py -s
```

> Запуск происходит в отдельных терминалах

## Переменные окружения

### Создание файла .env

В проекте мы пользуемся дебагером и некоторыми личными данными, которые не должны быть в репозитории

Создайте файл с названием ".env" в директории "backend"

### Шаблон файла

Файл должен иметь базовый шаблон с переменным окружением

```
DEBUG=True
EMAIL_HOST_USER=ВАША_ПОЧТА
EMAIL_HOST_PASSWORD=ТОКЕН_ПОЧТЫ
DEFAULT_FROM_EMAIL=ВАША_ПОЧТА
```

> записать данные нужно без пробела после "="

Если вы не знаете как добавить токен почты пишите в чат!

### 1. Просмотр веток

Сначало посмотрите какие есть ветки

```
git fetch
```
> Обновит ваши локальные ветки ваших коллег из репозитория

```
git branch
```
> Список локальных веток (т.е у тебя на компьютере)

```
git branch -a
```
> Cписок всех веток (локальные + удаленные на Github)

### 2. Выберите свою ветку

```
git checkout "название ветки"
```
> Переключиться на определённую ветку

### 3. Загрузить последних изменений в проект

```
git pull origin "название ветки"
```
> Вводи эту команду перед тем как работать (если ты работал сначало в колледже а теперь дома, и наоборот)

### 4. Сохранить изменения (когда поработал)

```
git status
```
> Покажет все твои изменения в файлах проекта

```
git add .
```
> Команда добавит все твои измения

```
git commit -m "комментарий"
```
> Подпиши что ты сделал, подписывай только по соглашению "строка - 68"

```
git push
```
> Отправь изменения в репозиторий

⚠️ Но сначало всё проверь перед тем как пушить!!!
- проверь отоброжаються ли серым эти файлы: db.sqlite3, venv, pycache (node_modules)
- запускаеться ли проект

> Если при заработке будут какие-то вопросы, пишем в чат и обсуждаем
